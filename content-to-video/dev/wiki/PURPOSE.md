# PURPOSE — 本技能存在的理由与不可破的不变量

WikiSkill 把 `PURPOSE.md` 放在 Skill Layer：它不是操作手册，而是**改动的最终
裁决依据**——当"某个改动能不能通过门控"有争议时，回到这里判断。

## 目标

把任意中文信息源（粘贴文本/上传文档/网页/资讯 API）**稳定地**转成一条配音 +
字幕 + 配图的解说视频。"稳定"是关键词：这条链路跨 TTS、搜图、渲染三个外部
依赖，任何一个抖动都可能让整次制作白跑。

当前对话模型负责**选题与配图评估**（判断力），脚本负责**确定性环节**（TTS、
HTML 生成、渲染、校验）。分工不可颠倒：能用脚本断言的，不要交给模型判断。

## 不可破的不变量

任何改动，只要破坏下面任意一条，**门控必须判红并回滚**：

1. **产物洁净**：制作产物（`segments_source.json`、`audio_output/`、`hf-project/`
   及其成片）绝不落在技能目录内。技能目录只放技能自身的源码/配置/文档。
2. **执行态轻量**：`SKILL.md` 是入口而非百科全书。深度内容进 `references/`，
   维护期知识进 `dev/`。执行态 agent **不得读取 `dev/wiki/**`**。
3. **环境声明诚实**：文档声明的依赖版本/默认值必须与代码、配置的实际值一致。
   宁可把门槛写低再实测，不可凭印象抬高。
4. **失败要说得清**：任何提前退出都要给出"下一步该干什么"，不能只报一个
   退出码。环境限制（缺编码器/缺 Key）必须与代码回归区分开报告。
5. **旁路不影响主流程**：trace、报告、缓存这类旁路机制，自己出错时静默降级，
   绝不能反过来搞挂一次视频制作。
6. **隐私**：轨迹/报告/日志里不得出现绝对路径、稿件正文、API Key。

## 权衡取舍的优先级

当两个目标冲突时，按此顺序让路：

```
不变量 > 可诊断性 > 一次制作的成功率 > 制作速度 > 成片观感
```

说明：宁可多花 30 秒 checksum / 多打几行 stderr，也不要"跑得快但失败时不知道
为什么"。渲染速度这类优化只有在前面几项都不受损时才值得做。

## 明确不做的事

- 不做英文内容（断句、音色、字体均按中文设计）
- 不做多轨剪辑、转场特效、BGM（Hyperframes 单条渲染路径，不引入剪辑器）
- 不为了"看起来聪明"而自动替用户做 expensive 的兜底（如静默批量生图消耗额度）
