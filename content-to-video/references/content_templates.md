# 更多内容类型举例

SKILL.md 正文讲了两种基础模式（精选摘要 / 完整讲解），下面是几种常见内容类型
具体怎么落进这两种模式——大多不需要新概念，只是选材角度和措辞不同。每个例子
只写 `segments_source.json` 的关键片段，其余字段（accent/speed 等）照常规写法。

## 章节编号 or 自然过渡（`flow` 字段怎么选）

写稿前先判断内容形态，决定要不要 `"flow": true`：

- **默认（章节编号模式）**：内容是并列的"条目"——新闻速览、多要点日报、
  播客观点摘录、周报播报。条目之间本质是并列关系，编号 badge + 开场目录 +
  accent 色 wipe 扫场能帮观众建立"第几条/共几条"的预期，保留板块感是优点。
- **`"flow": true`（自然叙事模式）**：内容是连续的"一条线"——单概念深入
  讲解（上文的反向传播就是）、书评/影评的情节脉络、产品评测的体验递进、
  故事叙事。段落之间是承接关系，编号和扫场反而会把叙事切碎；关掉编号、
  用更长 cross-fade 过渡，配上承接句，观感是"接着讲"而不是"翻页"。

判断口诀：**观众会不会用"第几条"来定位内容？会→默认；不会→flow。** 介于
两者之间（比如评测有 4 个独立维度，但每个维度内部是递进讲解）→ 按主导关系
选，然后靠写稿的承接句弥合。

### 承接句怎么写（flow 模式的命脉，章节模式也受益）

flow 模式下段落切换没有视觉板块语言，听觉承接就是全部——每个内容段的
第一句必须完成"从上一段到这里"的桥接。几种可用句式（贴内容选，禁止整期
视频同款句式复读）：

- 回顾式：上一段讲完 X，这段从 X 的余波或对照面切入。
  「看完 X 的发布，另一家也没闲着……」「X 的问题解决了，但代价是……」
- 递进式：X 与 Y 是层次/因果关系时用。
  「如果说 X 解决了"能不能"，那 Y 决定的是"好不好"……」
- 设问式：观众此刻正想问的问题。
 「那普通用户能感受到什么变化？」「这套机制的成本在哪？」
- 场景式：直接把观众放进下一个情境。
 「把镜头拉到用户这边……」「回到发布会现场……」

### 首次引入故事/案例：先铺场景，再进情节

承接句解决的是“段与段”的桥接；还有一个更隐蔽的坑在**段内部**：信源里的故事/案例
往往自带前文语境，直接摘中间最精彩的片段，观众会没头没脑。首次引入必须先用一两句
交代“人物是谁、在哪、之前发生了什么”，再进情节。

- 反例（从故事中段讲起）：“他伸手去拿第二柄剑，没想到重达七八十斤，直接脱手……”
  ——观众不知道这是谁、在哪、剑冢里一共几柄剑、第一柄发生了什么。
- 正例（先铺场景）：“金庸笔下，剑魔独孤求败晚年埋下三柄剑。杨过来到剑冢，先取
  第一柄锋利的紫薇软剑，再伸手去拿第二柄……”——多了两句铺垫，情节就立住了。

铺垫同样只限信源里有的信息，不得为了顺溜编造前情。

开场白/结尾段是承接链的头尾：开场交代"本期主题+为什么值得看"（自动预告
只做轻量 chips 露各段标题关键词，不做清单式剧透目录，flow 模式默认就是
chips 形态）；结尾回顾主线+一句收束，不要突然戛然而止。

## 产品评测 / 开箱解读

属于"完整讲解"模式的变体：不是按文档章节走，是按"评测维度"走（外观 → 核心
体验 → 优缺点 → 总结），信源通常是用户自己写的体验笔记、或几篇测评文章的
整合。

```json
{
  "segments": [
    {"title": "开箱与外观", "tagline": "第一印象", "text": "..."},
    {"title": "核心体验", "tagline": "实际使用", "text": "..."},
    {"title": "优点与不足", "tagline": "客观评价", "text": "..."},
    {"title": "值不值得买", "tagline": "总结", "text": "..."}
  ]
}
```

配图：产品实拍照片能拿到就用方式 A（文搜图，搜产品名+型号）；讲参数对比时
用方式 C（图表，比如跑分柱状图）；讲抽象体验感受（"上手曲线""操作逻辑"）时
用方式 B（ImageGen 意象图）。三种方式同一期视频里混用很常见。

## 周报 / 工作总结播报

"精选摘要"模式的变体：信源是自己这一周的工作记录/项目进展，从中挑 4-6 个
值得让人（团队、老板）知道的要点，用类似新闻播报的口吻讲出来，比一段段读
文字周报更抓人。

```json
{
  "opening": "大家好，这是我这一周的工作播报。",
  "segments": [
    {"title": "XX 功能上线", "tagline": "本周进展", "text": "..."},
    {"title": "遇到的问题与解决方案", "tagline": "本周进展", "text": "..."},
    {"title": "下周计划", "tagline": "展望", "text": "..."}
  ]
}
```

数据类进展（完成率、性能提升百分比）建议配方式 C 图表，比一句"提升了 30%"
配一张不相关的意象图更有说服力。

## 播客 / 视频节选摘要

"精选摘要"模式：信源是一段播客转写稿或视频字幕，目标是从中挑 5-8 个最有
信息量的观点/金句意思（不是逐字复述），做成"3 分钟看完这期播客说了什么"
式的摘要视频。

```json
{
  "segments": [
    {"title": "嘉宾观点一：XXX", "tagline": "播客名/嘉宾名", "text": "..."},
    {"title": "嘉宾观点二：XXX", "tagline": "播客名/嘉宾名", "text": "..."}
  ]
}
```

如果原节目本身就是"主持人 + 嘉宾"对谈形式，也可以用双人对话段落（见
SKILL.md 第 2 步）还原这种一问一答的感觉，而不是压缩成单人讲述——这种情况
下 `dialogue` 比 `text` 更贴近原节目的味道。

## 书评 / 影评

"完整讲解"模式的变体：按"核心观点/情节脉络 → 亮点 → 局限 → 值不值得看"的
结构组织，跟产品评测的骨架很像，区别是内容偏主观赏析而不是参数对比，配图
更适合走方式 B（书封/海报风格意象图，而不是数据图表）。

## 财报 / 数据报告解读

"完整讲解"模式，但**这是方式 C（真图表配图）用得最多的场景**：每提到一个
具体数字（营收、增长率、用户占比），配一张对应的柱状图/折线图/饼图，而不是
配一张"看起来像财报"的意象图或不相关的公司照片。

```json
{
  "segments": [
    {"title": "营收同比增长", "tagline": "2026 Q2 财报", "text": "..."},
    {"title": "用户构成变化", "tagline": "2026 Q2 财报", "text": "..."}
  ]
}
```

对应 `charts.json`（见 `references/image_options.md` 方式 C）：
```json
{
  "charts": [
    {"id": "seg1", "type": "bar", "title": "营收（亿元）", "labels": ["Q1", "Q2"], "values": [12.3, 15.8]},
    {"id": "seg2", "type": "pie", "title": "用户构成", "labels": ["个人", "企业", "教育"], "values": [55, 30, 15]}
  ]
}
```

## 怎么选：先看信源类型，不用死记模式名

不用纠结"这属于哪个模式"——回到 SKILL.md 开头那张对照表判断两个问题就够了：
1. 目标是从很多候选里**挑重点**，还是把这份材料**讲完整**？
2. 每个点要不要配真实数据（→ 方式 C）、真实照片（→ 方式 A）还是抽象示意图
   （→ 方式 B）？

答完这两个问题，写法就跟 SKILL.md 正文描述的完全一样，不需要为每种内容类型
单独学一套新规则。
